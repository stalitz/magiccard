## CP-SAT 精确求解器首次量化 sched_dp 真实 gap（用户批评混元"DP 是壳子包贪心"推动）

**判断**：全状态填表 DP 不可行（4★ 联合状态 ~10^26，宇宙年龄量级）；但 **CP-SAT 作业级 RCPSP 模型是正确工具，且天然把买卡/炉/偷炉/物料统一到一个状态空间**（正是"买卡/选炉/合成=同一 DP 状态转移"）。

**新建 `backend/engine_v2/tests/cp_sat_solve.py`**（ortools 9.15.6755，已装项目 venv mc）：
- 每卡种 need0[i] 作业实例，start/end/dur_tick（dur 全 45 倍数→tick 粒度）
- 机器 `AddCumulative`：主炉 3 / 买卡 15 / 偷炉 1；mclass=[0,2] 用 mode 二选一（分享 start/end）
- 物料 assignment boolean（每 j 产出单元至多一个消费者，`use⇒end[j]≤start[i]`）
- 目标 min makespan；1★/2★ box_cap(218)>Σneed0 → 宽箱不建约束
- 解出后**用 `_verify_sched.simulate` 独立复算**（铁律：不许自采信）

**★ 时间单位陷阱（2026-10-25 实锤，必守）**：时间单位必须取该 instance 全部 dur 的 **gcd**——1★/2★ gcd=45s，但 **3★/4★/5★ gcd=15s**（存在 24000/81600/31200/38400/110400/152880s 等非 45 倍数）。固定用 45 会让 `round(24000/45)=533` 压成 23985s（少 15s）→ CP-SAT 认为卡提前完成、与模拟器真实 dur 不一致 → 报「主炉超容 4>3」假不可行（曾误判 3★）。改 per-instance gcd 后 3★ 一次通过。

**★ 验证口径（重要）**：`_verify_sched.simulate` 因 sched 不带 machine mode，对 `mclass=[0,2]` 只能「必要条件」检验主炉容量 → **会保守误报超容**（3★ 曾报 4>3 但精确检查 OK）。故 CP-SAT 解用 `cp_sat_solve.precise_check`（按实际 mode 事件扫描）作权威容量检查 + simulate 验「物料+箱容」，双验证。

**结果（5 星全跑，precise_check + simulate 双验证 可行=True 且 makespan 一致）**：

| 星 | CP-SAT | bound | 状态/wall | sched_dp | gap |
|---|---|---|---|---|---|
| 1★ | 7.01h | 7.01h | **OPTIMAL** 11s | 7.04h | 0.4% |
| 2★ | 22.01h | 20.02h | FEASIBLE 180s | 25.02h | **13.7%** |
| 3★ | 67.35h | 66.68h | FEASIBLE 180s | 72.69h | 7.9% |
| 4★ | 73.35h | 72.90h | FEASIBLE 240s | 78.69h | **7.3% (5.34h)** |
| 5★ | 164.28h | 162.72h | FEASIBLE 240s | 164.81h | 0.3% |

**核心实锤**：
1. sched_dp 的「1★ root=7.04h 证最优」是**假象**——CP-SAT 证真最优 7.01h（低 2 tick），其可采纳 LB 不紧、自证了错误最优。
2. **sched_dp 全线非最优**：2★ 最差 13.7%、3★ 7.9%、**4★ 7.3%（5.34h）**、5★ 0.3%。之前「4★ 反超 HEAD 78.81h→77.45h」只是比烂基线好，离真最优（≤73.35h）**还差 5.34h**。
3. **gap 非单调**：宽而浅的 2★/3★/4★ 差 7~14%，深而窄的 5★ 只差 0.3%（长链关键路径锁死 makespan、调度自由度小 → sched_dp 易接近最优）。**sched_dp 的真正弱点是「宽 ready 集组合爆炸」**，不是高星。
4. CP-SAT 全线可行解都优于 sched_dp（5/5 星）；仅 1★ 证最优，其余 180~240s anytime 解但已胜出。
5. 规模：**5★ 只有 108 作业**（卡种少楼层高）反而比 3★ 191 / 4★ 248 小，vars 1233 vs 3523/5829。

**next**：生产化路径 = CP-SAT 离线出界（下界 + 好解）→ 滚动/anytime；或直接用 CP-SAT 解作骨架喂 dp_controller。4★/5★ 精确最优需更长求解时间或接受 anytime。
