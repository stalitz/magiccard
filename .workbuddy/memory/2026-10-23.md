## DP 每 tick 控制器·第 4 个实现瓶颈（"DP 慢于贪心" 根因，本日收尾）
- 上一轮修完 3 bug 后 DP 在 tid=59 done=1 但 76.84h，比贪心 73.41h 慢 3.4h。用户铁律：实现你说得算，若 DP 慢须 profiling 证瓶颈、不许说"DP 不行"。
- **根因 = 买卡层欠买**：旧 DP 控制器只在 t0 提取时买「本 tick 正在炼的精炼」的底料（base_need 现买+顺延1 tick），炉满时不买→下 tick 也无料→精炼顺延、炉空等料。贪心靠 `due` 前瞻预买（总炉数×3+6/tick、箱容闸门）让喂料提前到位。
- **修复**：新增 `DPTickController._jit_prebuy()`，按 net_plan 需求算 `due`（合成卡实例底料喂料 + collect 在即收藏底卡）轮转预买、`free_after-预留(len(furnaces)+2)` 防撑爆、`buy_cap=总炉数×3+6`；放在 skip-solve 前（炉全忙也持续预买）。t0 提取改**纯顺延**（底料不在箱就跳过，由预买保证下 tick 到位），买与精炼彻底解耦。删冗余 Step5 收藏底卡补齐；新增 `bounded_count` profiling。
- **数据(tid=59, 1轮)**：修复后 DP **72.06h / 5765 tick / 84.0%** vs 贪心 73.41h / 5873 tick / 83.1% → DP 快 1.35h，精炼 55 vs 56、买卡 136 vs 139，零溢出/零错误/零买卡失败。差距纯属实现层买卡策略，对齐贪心 JIT 后 DP 回到最优+微胜。
