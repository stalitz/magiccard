## ⚠️ 服务停摆事故：stop→start 端口竞态（2026-09-14 18:25 定位）

**现象**：用户报「服务怎么停了」。`./server.sh status` = NOT running，`:8000` 无监听。

**根因（我的操作失误）**：15:40 我执行 `./server.sh stop; sleep 1; ./server.sh start`——
旧进程刚收 SIGTERM 时 `:8000` 仍处于占用态，新实例 **bind 失败（`errno 48 address already in use`）立即退出**，
而旧实例已被 `pkill` 杀掉 → **服务静默停摆约 2h45m**（日志中该报错累计出现 4 次 = 历史上至少踩过 2 次）。

**放大器（真正该修的）**：`server.sh start` 原实现无论成败都 `echo "started -> ..."`，
我当时只 `tail -2` 看到 "started" 就以为起来了，**没有 curl 校验** → 故障 3 小时后才被用户发现。

**加固**（已改 `server.sh`，串行 Edit）：
- `stop`：pkill 后**轮询等端口真正释放**（最多 20×0.3s），仍占用则告警。
- `start`：起后**自校验** `:8000` 是否在监听（最多 10×0.5s），失败则打印日志尾部并 `exit 1`。

**验证**：用当时同样的竞态（`stop` 后**不加 sleep** 立即 `start`）实测 → `stopped` / `started` / `RUNNING on :8000` 全绿。

**教训**：**任何"重启服务"的操作，最后一步必须校验端口/接口（curl），不能只信脚本的 echo。**
该条已同步进 MEMORY.md 的铁律区。
