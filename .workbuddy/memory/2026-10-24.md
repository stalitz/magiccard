## sched_dp 求解器修复 + DP 控制器全量 bench（#94 完成，接上文端到端验证之后）

### 修复的 5 个求解器 bug（sched_cmp/sched_dp.py，均经独立模拟器 _verify_sched 复算）
1. **返回值漏 t_rel → 幻影最优**：dfs while 循环内「收卡/推进到下一完工」耗时没计入返回值，memo 存偏小相对值。1★ root=6.03h < 真实 7.03h 且违反自身下界 6.5h；旧代码正确纯属叶子赋绝对值侥幸。
2. **rec 库存恢复 `+=k` 应为 `+=c*k`**：c≥2 库存污染→枚举不完整→bounded=False 是假证明（4★ 全量 82.05"最优" vs 截断实找到 78.05）。
3. **买卡 op 时刻丢失**：「无向量→推进时间」分支 continue 丢 buy_path → t=0 买卡记成 t=45s。改 cur_path/own_ops 贯穿 while。
4. **memo 调度丢失两连**：memo 命中跳过叶子→最优调度永不记录（memo 改存 (值,后缀链)+根后缀重建）；link() 重建首轮覆盖 cells[-1] tail→子树后缀被甩（64→31 ops）。
5. **memo 后缀跨迭代混入**：memo 键=迭代顶状态但后缀含全部 own_ops 会重放前序买卡 → memo 存「迭代顶起」后缀、返回存「调用入口起」后缀（双链：best_suffix/best_memo_suffix）。
- 另修 INF 不落 memo（LB 剪枝 INF 依赖绝对口径 best["val"]，非状态纯函数）。
- 性能：_SearchAbort 回卷+每32步查 deadline+maximal 容量快路径/叶态直用+LDS max_vecs=96/rec_budget=50000。4★ 22s/15节点→0.05s/913节点。

### 紧箱 DP 控制器性能修复（streak 假过时 + relax 双倍预算，bench 后追加）
- **现象**：紧箱 60 格·各2轮 DP 段 24 分钟没到 tick 5000（预估全程 5h+）。500 tick 探针：墙钟 139.2s 里 solve 占 139.0s、resolves 69（streak 触发 66）。
- **根因链**：① streak 判定把「等料」当「骨架过时」——头动作喂料不齐时连续 20+ tick 零动作（等 reactive 买卡落箱/等炉出货），streak_limit=4 → 每 4 tick 一次重解级联；② 每次承诺点「有约束解 2s + 箱容超限 relax 回退再 2s」= 4s（solve_max=4005ms 实锤）；③ 60 格几乎必触发 relax（DP 有约束 incumbent 峰值 61>60）。
- **修法三连**（均不改调度语义，仅节流）：① streak 判定加**等待过滤**——头动作缺的喂料「在炉即将完工（endtime<=now+2tick）或本 tick 刚买（bought_this_tick）」= JIT 正常物流等待，不累积 streak；② relax 回退预算砍到 min(0.5s, time_budget)——只要可行 UB（_ub_schedule 初始 incumbent 本就合法）；③ 退避计数 `_no_progress_resolves`（cap 16）防「重解微推进」型级联，**只有 n_ref>0（真实精炼）才清零**（买卡/cursor 微推进都不算——紧箱几乎每 tick 有零星买卡）。
- **失败尝试记录**：streak_limit 粗调 4→20 让 4★ 单套 incumbent 退化（78.81→84.14h，重解时机对 anytime incumbent 敏感）→ 证明必须按等待语义精准过滤，不能调阈值。退避清零用「cursor 前进」也失效（重解一次挤出一个 op 的蠕动形态）。
- **效果**：500 tick 墙钟 139.2→35.7s（4×）；4★ 单套回归 78.81h 与原 bench 完全一致（relax 0.5s 对宽箱零影响——4★ 不触发 relax）。

## 紧箱饥饿根治：JIT 门 + 腾箱（#96，2026-10-25，dp_controller.py）

### 根因（机制级，非阈值级）
pass 1 reactive 买卡只受**箱预算闸**约束（无 JIT 纪律）→ 宽箱把整套底卡一次性买齐（4★ 峰值 201/218、94% 底卡=10-22 已实锤的假象）→ 紧箱 60 格箱被囤到硬顶 → 买卡闸 box_free-reserve 吃光 → 头 op（buy）永发不出 → cursor 冻结饿死（done=0/4、槽占 21.5%、分岔性两态）。**DP 骨架带箱容约束（静态投影≤60），是执行层把未来 buy op 提前拉齐打破投影**。

### 修复（dp_controller.py，两件）
1. **JIT 门**（`_jit_due` + pass 1 门禁）：due = 未发 refine op 中「非底卡喂料已齐（可炼）」者的底卡喂料毛需求（同贪心 Step-JIT 口径，depth-1 首 tick 拉动、逐层 JIT）。喂料底卡只在 `箱内+炉内+本 tick 在途 < due` 时放行；**op 不标记 issued**（前沿需求增长再放行）。纯收藏底卡（`_feeder_cids` 之外）不走门（专辑预买/终局 op 拉起）。保留「不过 start 门」（防消费者等落箱空转），只把买量上限改为 **due ∩ 箱预算**。
2. **腾箱**（`_box_compaction`，同贪心 Step4）：change_free<=2 或 box_free<=4 触发；卖多余 **10 面**底卡（双箱、保留 max(1,due)、回减 plan["bought"] 账；铁律只卖 10 面，tid=709 的 57 面底卡也不卖）+ 挪多余合成卡进保险箱（保留未发 op 需求、预测 sim 首空位、修 avail_slots 防悬空槽位）。sell/move 先于 buy 执行 → 腾出位当 tick 可用。每次腾箱记 1 discrepancy（→ disc_over 重解）。
- 附带：`bought_this_tick` set→Counter（在途计数）；新统计 jit_blocked/compact_sold/compact_moved 进 dpstats。
