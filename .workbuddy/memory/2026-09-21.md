## 自动挖地修复（窗口边界炸弹约束 + 失败动作排除）+ 真机下推 5 层验收

### 根因（"一层都走不动"）
- 旧 `auto_loop` 失败只 `continue`，**不把动作排除** → 每轮重选同一个边界炸弹格，3 次失败即停。
- 真凶是**地图窗口边界炸弹约束**（实机 `dig_probe_raw.py` 验证，非限流）：
  服务端只下发 8 行窗口 `dig_index-5..+2`；**炸弹爆炸范围探出这 8 行 → 返 `code=-1`(desc="system busy")，
  但属「目标非法」非限流，重试无用**。
  - 九宫格(覆盖行±1) → 落点行必须 ∈ `[lo+1, hi-1]`
  - 超级炸药(覆盖行±2) → 落点行必须 ∈ `[lo+2, hi-2]`
  - 一字型(横向不出行)/锄头(单格) 不受限
  - 顶行**本身没冻结**（旧锄头失败是那格已被挖空，返 -1"目标不可挖"），只是炸弹越界被拒。

### 修复
- `backend/dig_plan.py` `candidates()` 加窗口边界约束 + `(行,列,工具)` 排除集：
  九宫格/超级炸药落点先 `blast_ok(dt, L)` 校验不越出 8 行窗口；其余炸弹礼物、超级炸药格同判。
- `backend/dig_auto.py` `auto_loop`：失败动作 `(line,col,dt)` 记入 `failed` 排除集、下轮换动作重规划，
  不再死磕；连续 3 个不同动作失败才停（疑限流）。
- `tools/dig_plan_check.py` 新增第 5 组"窗口边界炸弹排除"断言（九宫格不能选 lo/hi，可选 lo+1/hi-1；
  超级炸药不能选 lo/hi，可选 lo+2/hi-2），旧 21 项 + 菱形 8 项全过。
- `tools/dig_auto_drive.py`（驱动真实自动挖：轮询 `/api/dig/state` 读 `auto` 字段，推进满 N 层自停；
  初版调 `/api/dig/auto/status` 404 → 改只读 `/api/dig/state`）、`tools/dig_diag.py`、`tools/dig_probe_raw.py`。
