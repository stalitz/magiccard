## 「多炼 2 次」是统计口径错 + 2.2h 拆解（用户二次质疑成立）
用户：「1 tick 只有几十秒，先买后买没区别，不至于差 2h，也不该多炼 2 次，多炼的炼的是啥」。

1) **没有多炼**：`_probe_refine_diff` 把 DP炼卡+DP偷炉 全记下来：两条轨迹总炼卡 **55 = 55**，
   卡名多重集逐项差 0。`Engine.stats["refined"]` 只数 `_REFINE_TAGS` 里的 DP炼卡（不含 DP偷炉）
   → 「42 vs 44」其实是「主炉 42+偷炉 13」vs「主炉 44+偷炉 11」，工作总量相同，只是活从
   偷炉挪到主炉。**以后对比炼卡量必须把偷炉算上。**
2) 预买唯一的**物理**作用：炉收那一刻料在不在箱。不预买 → 炉收本 tick 才买 → 下一 tick 到
   → 该炉空 1 tick。3★ 一轮 55 次投炉 ⇒ 硬上限 55×45s = **0.69h**，不可能 2.2h。
3) 超出部分的来源：料在不在箱 → DP 解出不同排布。两条轨迹卡名序列**第 7 步就分叉**
   （保底=金毛寻回犬 / 不预买=博美），总量相同、尾部等待不同。
4) 波动带（`_probe_noise`，budget 0.06/0.1/0.2/1.0）：保底 **72.10~72.78（Δ0.68）**、
   不预买 **73.67~74.33（Δ0.66）**。两组不重叠 → 有 ~1.6h 系统性差，但成分 = 0.69h 物流
   + ~0.9h 解分叉，且方向不稳（4★ 反向 −2.5h）。
5) 结论：物理可证只有 ≤0.7h（≈1%），不足以支撑「紧箱囤 3 张」；而紧箱占位的代价是
   取卡失败→炉不释放→死锁。6d2f7b8 的「保底一波」依据不成立，建议退回炉满一张不买。

## 「一个 tick 能做到什么」实测（`tests/_probe_tick_capacity.py`，3★ 600 tick）
用户追问「那你一个 tick 能做到什么」。统计每 tick 的 actions：
- 分布：**98.7% 的 tick 是 0 投炉**，1 炉 0.8%、3 炉 0.5%。
- 「有空主炉却 0 投炉」**只有 3 tick（0.5%）**，原因全是「本 tick 在买卡」。
- 同 tick 投 ≥2 炉：3 次，最大 **3 炉**（t=225s 空 2 主炉 + 1 偷炉一 tick 投完）。

→ 结论修正：
1. 「一个 tick 只做一件事」不成立。执行层 scan_window=6、无「投一炉就 break」的硬限，
   料在箱 + 炉位够时可连投（实测 3 炉/ tick）。98.7% 空转的真因是**4 个炉都在炼**，
   45s tick 下 3600s 的炉要 ~80 tick 才空一个。
2. 我之前把 2.2h 归因为「预买省下 55×45s 物流」→ **假的**。实测真空转上限只有
   3 tick = 0.04h。2.2h 全部是 DP 解分叉（换初态→不同排布），方向不稳（4★ 反向 −2.5h）。
   → 用户「先买后买没区别、不至于差 2h」两句都成立。
3. tick0 投不满的真因仍是骨架粒度：tick0 箱 0 料，投 3 主炉要 9 张不同底卡，
   `jit_need` 是头 n_wave 炉缺口**去重并集**（3★ 约 6 种）→ 最多 1~2 炉。

## 「买卡不该占 tick」诊断成立 + 三档口径全负收益（ee0221d，默认关）
用户：「买卡不是瓶颈，所以买卡不应该单独占一个 tick，也不应该算到单独的解」。

**诊断：两句话都对，代码里确有两处人为「买卡占 tick」：**
1. `sk["dur"]` 把底卡建成 **dur=45s 的调度节点**（物理不存在：真机 code=0 即落箱、
   仿真 EP_BUY 即时 `_add_to_box`）。
2. pass2 `f in bought_this_tick → blocked`，本 tick 买的料不能当喂料。

实测自造回环（3★ 空炉起步）：tick1 买 143~148 全被排他 → tick2 又买 144~148
（143 因 planned_buy 用完跳过）→ 只剩 143 单张凑不成配方 → tick3 才投第 1 炉。
三 tick 花 11 张料只开 1 炉，箱空 18→12→7。

**三档实测（3★ 18/200 单套1轮）：**
| 变体 | 口径 | h | 炉占 | 炼/买 |
|---|---|---|---|---|
| AD | 现状 | **72.10** | 83.9% | 42/150 |
| ST | 解排他，dur45 | 75.39 | 80.3% | 45/142 |
| ST1 | 解排他+不保底 | 73.41 | 82.4% | 43/142 |
| ST2 | 解排他+dur0+保底 | 74.06 | 81.7% | 43/146 |
| ST2L | 解排他+dur0+不保底 | 73.41 | 82.4% | 43/143 |

→ 解除排他 = op 比计划 start 早发 1 tick = **占掉关键 op 的炉位**（与「未到期 op
提前发 75.49→79.46h」同源）。dur=0 无救，因为 solver 在「买卡零成本」下解出的
排布本身更差。★教训：物理正确 ≠ 解更好；DP 的解对「买卡要 1 tick」这个假设敏感，
该假设反而起到给买卡留缓冲、防急抢炉位的作用。

**开关**（默认关，关闭路径与基线逐位一致）：`MC_BUY_SAMETICK=1`（虚拟负槽 + 解排他 +
`Action.feed_cids` 买后重读按 cid 现查槽位）、`MC_BASE_DUR0=1`（底卡 dur=0），必须同时开。

**真正该做的（未做，大工程）**：买卡从搜索空间彻底拿掉，改成 refine 的**即时前置约束**
（零耗时、只受箱位/金币限制），而不是「零耗时的节点」——后者仍被时序门当排期对象。

## 买卡移出「解」：单轮正收益、多套退化 33%（5483e71，默认关）
用户授权：「10 面额卡可以认为本身就存在，随时买、不花 tick，但一定要改对，不要死锁或囤卡」。

**做法**（`MC_BUY_FREE=1` + `MC_BUY_SAMETICK=1`）：
1. `_ub_schedule` 底卡不占 shop 时间槽、买完当场进 stock（同 t 可用）、只受箱容；
   ub 里底卡完成时刻不计 makespan。2. `_solve_plan` **不生成 buy op**。
3. pass1 改走 `jit_need` 即时补料（base_quota / 箱空位仍是闸）。
4. 负号虚拟槽 + `Action.feed_cids`（买完重读、按 cid 现查槽位）。

**单套单轮（AD→BF）**：1★7.08→7.06 / 2★23.07→23.06 / 3★72.10→72.75(+0.65，噪声带内)
/ **4★81.47→80.06(−1.41)** / 5★164.35→164.84。买卡数普遍 −5%（150→142、191→182）。
机制：旧版 tick1 买 6 张全被排他、tick2 重复买 5、tick3 才投第 1 炉；新版 tick2 一 tick 投满 4 炉。

**多套多轮（否决项）**：178 3轮 15.15→17.06h(+12.6%)；**85 3轮 21.11→28.09h(+33%)，
多炼 9 次、多买 15 张** → 囤卡+无效炼形态，判定没改对，默认关。

**已排除**：`MC_UB_ONLY=1`（跳过 dfs 只交 UB，消除 UB/dfs 口径不一致）→ 85 30.06h、4★ 85.39h
都更差 → 口径不一致不是主因。

**待查根因**：`jit_need` 是**全局**头 n_wave 炉缺口，不区分 DP 多轮/多套推进 → 多套下买卡
窗口与轮次错配 → 重复买 + 多炼。下一步让缺口跟随 `sets_fn` 的轮次推进。

## 多套退化真因 = 删 buy op 导致 ops 空 → 空转（3adff77）
用户：「继续查，查到问题就修」。

**定位**（`tests/_probe_multi_bf.py` 逐 tick 打点，tid85 三套）：
BF 在 5.06h~7.05h 空转 **160 tick**，`resolves` 1→161，其中 803 次是 `exhausted`，
重解出的 `plan_ops` 首次 17、之后**全是 0**。

**根因两条（同一处）**：`buy_free` 时 `_solve_plan` continue 掉所有 buy op，指望 pass1
的 `jit_need` 补料；但 jit_need 是从 `ops[cursor:]` 的 **refine op** 反推的：
1. 非底卡需求归零（都在箱/在炉）、只剩底卡要买 → `need0` 空但 `buy0` 非空 →
   「无需求不解算」保护（`not need0_map and not buy0_map`）不触发 → 解出只有底卡节点的
   sched → 被全部 continue → **ops=[]**；
2. `exhausted = cursor>=len(ops)` 在 ops=[] 时**恒真**（0>=0）→ 每 tick 重解还是空 →
   死循环；ops 空 ⇒ jit_need 空 ⇒ **一张底卡不买** ⇒ 有炉位无料可投。

**买卡 op 的双重身份**：① solver 排期节点（该删，物理无 45s）；② 执行层「买卡需求清单」
（**不能删**，pass1 就是照它买）。5483e71 把两者一起删了。

**修法**：`MC_BUY_KEEPOP` 默认 **1**（buy_free 时保留 buy op，零耗时/不计 makespan）；
`exhausted` 加 `len(ops)>0`（消除 803 次空算）。修后 85 三套 28.09→**20.07h**（炉占
82.8%→97.1%，炼 42→33）。`MC_BUY_KEEPOP=0` 复现病态档。

**但 buy_free 净收益仍不成立 → 默认继续关**：
| 场景 | AD | BK | Δ |
|---|---|---|---|
| 1★85 单轮 | 7.08 | 7.05 | −0.03 |
| 1★85 三套 | 21.11 | **20.07** | −1.04 |
| 1★178 三套 | **15.15** | 17.07 | +1.92 |
| 2★290 | **23.07** | 24.04 | +0.97 |
| 3★59 | **72.10** | 75.39 | +3.29 |
| 4★60 | 81.47 | **80.05** | −1.42 |
| 5★709 | 164.86 | 164.82 | −0.04 |

★ **BKN（buy_free+keepop，不解除本 tick 排他）= 与 AD 逐位相同**（3★72.78/2★23.07/
4★81.47/1★7.08）→ 不解除排他时 buy_free 收益为 0：执行层「买卡占 1 tick」的缓冲与
solver「买卡零耗时」口径互相抵消、闭环自洽。BK 的差异**全部来自 `MC_BUY_SAMETICK`**
（提前 1 tick 投炉），有正有负（3★ +3.29h = 老结论「提前发占关键 op 炉位」复现）。
→ 物理正确 ≠ 解更好：虚构的 45s 正在给买卡提供 1 tick 缓冲，删掉换不到净收益。

## 「删掉 45s 换不到净收益 = 实现有问题」—— 查出 4 处，修完单轮全转正（aa5ad66）
用户：「删掉它换不到净收益, 说明实现的有问题, 把问题找出来」。

**1) 主因：buy_free 只改了 `_ub_schedule`，`dfs` 一行没动**
dfs 里买卡仍 `running_rel += ((b, dur[b], 1))`（45s class-1、占 shop 槽、走 LAG）。
→ 交付解（dfs）仍是旧口径；同时 UB 变紧 → `best["val"]` 变小 → `t+lb>=best` 剪枝更狠
→ 更多时候直接交 UB 的贪心列表调度。锚点：BKN（buy_free+保留 buy op+不解排他）与 AD
**逐位相同** → buy_free 在 solver 侧零影响，只改了上界数值 → 这就是「换不到净收益」的真相。

**2) 下界链 `_chain_avail_rel` 对底卡返回 DUR=45s** → 新口径下高估、不可采纳 → 剪掉最优。

**3) buy op 留在 ops → cursor 钉死**（buy_free 让 solver 把终局收藏底卡也排 t=0；
JIT 门拒绝买它但不标 issued → `while issued[cursor]` 停在 0 → head_due 恒真 → streak
每 tick +1 → 每 4 tick 白解 → 尾部 2h 空主炉零动作）。3★：留 op 73.41 / 删 op 70.74。

**4) ops 空（只剩底卡要买）⇒ jit_need 空 ⇒ 一张不买，且不重解**（exhausted 有 len>0
守卫、head_due 不成立）。85 三套 t=20.0h 起连续 2h 零动作。

**修法**：`sched_dp.BASEFREE` 全局（dfs 买卡即时入箱+不占槽+买后 `_ready_items` 重算；
`_chain_avail_rel` 底卡返 0）；controller 侧 buy_free⇒buy_sametick 联动、buy op 默认不生成、
`jit_need` 空时按 `buy0_map` 兜底（门栏：非底卡全在箱）、空计划 `state_sig` 变化即重解。

**单轮五档（AD→BF）**：7.08→7.04 / 23.07→23.04 / **72.10→70.74** / **81.47→80.74** /
164.89→164.84；买卡数 150→142、191→185、87→81。

**多套仍亏**：85x3 21.11→22.06、178x3 15.15→17.06。逐 tick 打点（`_probe_bf_idle`/
`_probe_stall_state`）显示两档都卡在「`need0={}` 但套装未齐」：178 从 2h 起 nops=0、
2 个空主炉、1038 tick 零动作 → **`net_plan` 对「既作套装卡、又作上层喂料」的中间层
漏算需求**（planner 既有缺陷，与买卡口径无关）。AD 因 buy op 顺手多买底卡掩盖了一部分。
→ `MC_BUY_FREE` 仍默认关。★教训：改口径必须**全链路同口径**（UB/dfs/LB/执行层），
只改一层等于把「解」和「界」撕开，净收益必然为 0 或负。

## 23) 用户定调「DP 算的是投炉顺序，不是第几 tick 投哪个炉」+ 两轮消融（开关默认关）
前提核实：`sched_dp.dfs` 返回 `t_rel + best_v`，`best["val"]` 是**绝对完工时刻**
→ 优化目标是 makespan；`op["start"]` = 「该最优序下最早可开工时刻」= **下界**，
不是执行指令。旧执行层 `if op["start"] > elapsed + EPS: break` 把下界当上界用。

**消融 A：`MC_ORDER_ONLY=1`（投炉、买卡都不看 start，料齐+炉空即发）**
| 档 | AD | 纯顺序 | Δ | 炼次 | 买卡 |
|---|---|---|---|---|---|
| 1★85 | 7.08 | 7.06 | −0.02 | 12→12 | 52→52 |
| 2★290 | 23.07 | 26.06 | **+2.99** | 20→21 | **87→109** |
| 3★59 | 72.10 | 71.45 | −0.65 | 42→41 | 150→156 |
| 4★60 | 81.47 | **77.41** | **−4.06** | 44→41 | 191→191 |

**消融 B：A + `MC_BUY_GUARD=1`（投炉豁免，应急买仍守 start）**
1★ −0.02 / 2★ +0.97 / 3★ **+2.68** / 4★ −0.06 / 5★ −0.04

**结论**
- `start` 门的真实作用是**抑制「未到期就买」**，不是限制投炉（A 里 2★ 买卡 87→109
  就是未到期 op 被误判「到期缺料」→ 应急买连锁）。
- 但两者耦合，拆不干净：4★ 的 −4.06h **恰恰依赖未到期也买**（早备料→早开炉）；
  3★ 反而在「守买」下更差。→ 不存在「投炉豁免+买卡守」的干净拆分。
- 净效果分档：紧箱深链（4★）早发有利；宽 ready 集（2★/3★）有害。与既有结论
  「3★ 弱点=宽 ready 集组合爆炸」「禁据 1/2/3 星外推」一致。
- 五档逐位回归：默认路径未变（7.08/23.07/72.10/81.47/164.35）。两个开关默认关留作消融入口。
