## 2. 三玩法自动相互独立 + 修穿越手动按钮报错（app.js v20260916c / spirite_auto.py）
- **根因 ①（手动按钮报错）**：`/api/spirite/across/run` 末尾调了 `spg.remember(...)`，但 `spirite_progress` 自规则推导改造后已**删除 `remember`** → 500。已删除该行，手动历练恢复正常（默认选中改由 derive 规则推导，无需 remember）。

## 2. 切 tab 零请求 + 状态同屏

- 诊断：`spSetMode()` **本来就不发请求**，但**切完 tab 不重渲染状态条**，要等下一轮 `spTick`（原 8 秒）才变 → 用户感受为「每次切换都要加载状态」。
- 改：`spSetMode()` 末尾 `if (spLastData) spRenderState(spLastData);` —— 用缓存立即重渲染，零请求。新增 `spLastData` 保存最近一次 act=1 响应。
- 新增**三行同屏状态面板** `#sp-all`（大地图 / 荒岛 / 穿越丛林）：各显示进行中状态或今日次数 + 「能去的最新关」+ 「下一关…需先过大地图 X-Y」卡点原因；点击行即切玩法。CSS 加在 index.html `<style>` 末尾。
- 轮询 8s → **15s，且 `document.hidden` 时跳过**。
- 下拉给未解锁项加「· 未解锁」标注（`spUnlockedSet()`；大地图返回 null 不标注）。
- 修正 `spStageInfo`：荒岛/穿越的 `open_c/open_s` 文案改为「解锁：大地图 X-Y 关已通过」；穿越的本关坐标改用 `(章, index)` 显示为「1 级地图 X · 2 级地图 Y」。

## 3. 状态面板「一会显示有 / 一会显示无」闪烁修复（spirite_auto.py）

- **现象**：自动跑某套玩法时，主状态区每隔一会就从「进行中/有」闪成「无（当前 …）」，再被覆盖回「有」。
- **根因**：前端有两条刷新链同时写 `spRenderState`：① `spPoll`（自动跑时每 3s）渲染**引擎 `last_state`**；② `spLiveTimer`→`spTick`（每 15s）渲染 **`/api/cat/travel`** 的 act=1 状态。
  而 `_snapshot` 之前是 `last_state.island = d.get("island")`、`last_state.across = d.get("across")` —— act=1 原始响应**根本没有** island/across 子对象（那是 `cat_travel` 额外 enrich 出来的），于是引擎态的 `island/across = {}` → 渲染成「无」；15s 后 travel 态又把它覆盖回「有」。两个数据源口径不一致 → 闪烁。
- **修复**：`_snapshot` 现在按 `cat_travel` 的同一口径补建 `island`/`across` 子对象（`island.spirites/explore_ts/today_cnt/place/seq`、`across.used/ts`，取自 `hy_*` 与 `torrid_zone_*`）。引擎态与 travel 态从此完全一致，轮询覆盖不再跳变。
- 验证：直接调 `_snapshot(act1_含_hy_explore_ts)` → `last_state.island.explore_ts=1700000000 / spirites=[1,3,5,7,9] / across.used=3`（修复前三者分别是 0 / [] / None）；两端点 curl 200 无 500。

## 4. 「没有次数了还显示自动中」+「不显示还有几次」修复（app.js v20260916d / spirite_auto.py / main.py）

- **现象①**：灵宠探险（地图）免费次数已用尽，但「● 自动中」徽标一直挂着；荒岛探险已完成却不自动收、且不显示剩余次数。
- **根因①（徽标卡死）**：后端三个引擎**跨页面刷新常驻**（`_ENGINES` 进程级单例），但前端的 3s `spPoll`（驱动「自动中」徽标的 `spAutoModes`）**只在 `spStart` 里 `setInterval` 启动，页面加载时只调了一次 `spPoll()`、没起定时器**。于是刷新页面后若后端引擎仍在跑，徽标只被刷新一次就冻结——引擎跑完后前端再也不轮询，徽标永远停在「自动中」。引擎本身没问题（模拟：map free=0 起步正确输出「免费次数已用尽，结束」；island 进行中能正确自动收）。
- **修复①**：`spPoll` 改成**自维持**——`if (anyRunning && !spTimer) spTimer = setInterval(spPoll, 3000)`；这样加载时若后端有引擎在跑，单次 `spPoll()` 会把定时器续上，引擎结束后下次轮询即清徽标并停定时器。
- **现象②（不显示剩余次数）**：荒岛/穿越只显示「今日已用 N 次」，没有剩余。act=1 不回每日上限，需前端默认。
- **修复②**：`spirite_auto.py` 加 `ISLAND_DAILY_MAX=5`；`start()` 里 island/across 分别把 `daily_max` 默认填 5/10（可被 opts 覆盖，仅用于展示与到点停，不强制）。`cat_travel` 的 `island`/`across` 对象补 `daily_max`（5/10）。前端 `spRenderAll`/`spRenderState` 据此显示「今日 N/M 次 · 剩 K 次」。
- **附带健壮性**：map/island 收获连续失败 12 次即主动 `break` 停循环，避免「收获未就绪」死循环导致徽标卡「自动中」永不消失。
- 验证：`daily_max` 默认值正确（island=5/across=10/map=0）；前端文案 PASS（进行中/剩N次/缺字段兜底均正确）；后端 py_compile + 前端 node --check 通过；服务已重启（仅 :8000）。

## 5. 翻牌/取卡奖励显示数字 → 用道具字典翻译（app.js v20260916e / prop_dict.py / mc_api.py / main.py / auto_refine.py）

  4. 前端 `lotPaiOnce` 改读 `it.text || it.name || ...`（不再读不存在的 id 兜底）。
  5. `auto_refine.py` 自动炼卡取卡翻牌的日志 `detail` 改为直接用 `message`（去掉结构化 items 的 repr）。
- **验证**：端到端 mock `open_pai`：`48_1415_1,57_0_2` → `五彩石×1、灵力果×2`；空 content → 「翻牌成功」无 items；busy → 正确提示。py_compile + node --check 通过；服务已重启（仅 :8000）。
