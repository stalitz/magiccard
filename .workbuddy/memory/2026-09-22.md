  **绕过了 `_gift_name()`** → override 形同虚设。修：改成调 `_gift_name(t,i)`。

### ① 文物「一键上交全部」只交本次收获 → 改为遍历全部
- **先摸清事实**（`Downloads/wadi.har` 37 条 + 实机探针）：
  - `act=7` 收鉴定产出 → `76_0_1`（76 类=文物）；`act=10` 上交 `num=1&id=<76 sub-id>` → `69_<卡id>_<num>`。
  - HAR 里用户交了 **id=0 和 id=3**，而 HAR 的 act=7 **只产出过 76_0** → **id=3 是更早会话留下的
    → 服务端有持久文物库存**（这推翻了「只存在于本次收获」的旧判断）。
  - ⚠️ **原始 act=1 全字段实测无任何 76 类字段**（bag 只有 70 类 11 件材料）→ **没有只读的文物库存接口**，
    只能遍历探测。游戏里这功能文案叫「**兑换**」（「鉴定所获得的古文物或碎晶石可用于兑换卡片」）。
- **id 空间 = 挖地套卡序号（两条锚点精确命中）**：`76_0` → 卡 8396 = 套卡[0]「上古神兽」；

- **两种失败形态**（**打乱顺序**探针实测，code **随 id 走、与请求顺序无关** → 不是限流）：
  `code=-1`+system busy = **服务端认得该 id（存在、只是没库存）**，实测 id 0/1/2/3；

  `retries=1`（默认 3 会把 `-1` 当限流退避白等 3 轮）。
  真机：**tried=7 / not_exist=[4,5,6] / 14.5s**（旧「盲遍历 34 套卡」版要 **79s**）。
  路由 `POST /api/dig/relic/submit_all` + `GET /api/dig/relic/kinds`。
