## 三个真机 bug：DP 预买冻死 / 偷炉选自己 / 换卡箱被杂卡锁死

用户报「4821992 一下买了 3 个一样的 10 面，偷炉不开始，排队也不进」，
一开始查本地 8000（记忆约定默认本地），用户纠正：自动跑在云端 8001。
（云端日志时间戳是 **UTC**，op log 是前端本地时间，两者差 8 小时，别被 04:40 骗。）

### 1) DP 预买被「凑齐边界态」冻死（提交 `a95818f`）
- 现象：云端 4821992 / tid=321「珍稀动物」，04:05 之后 35 分钟零动作，
  日志只有 153 条「买卡 …（DP预买）暂缓：两箱空位只够凑齐本套」。
- 根因：`_is_collect_essential` 用 distinct 口径（箱里没有这张卡才算缺）。
  这套 47 张底卡里 `小头鼠海豚` 一个 id 要 7 张（1 进册 + 6 当三个 40 面中间卡
  的共用素材），箱里已有 3 张 → 判"不缺" → 预买全延后 → 底卡进不来 → 素材不齐、
  偷炉没料、出炉无卡可投。
- 修：判据换成 `net_plan` 净需求树（箱内 + 在炉之外还要不要它），并加 `as_take`
  区分语义 —— **取卡**要先把这张从在途扣掉（否则炉里那张正当需求的卡会被判
  "不需要"），**买卡**不扣。加 `_net_now` 按家底签名缓存 net_plan。
- 四场景回归全过（tid=54）：炉里第二张 81 必需 / 箱里已有 2 张 81 可延后 /
  炉里 82 必需 / 箱里已有 1 张 82 时第二张可延后。

### 2) 逃逸阀（同提交）
`_dp_refine_all` 本 tick 没有任何 refine 动作时，不延后预买 —— 保格位的前提是
真有东西要投炉；没有可投的，格位留着也是空着。否则 A 之外还会二次冻死。

### 3) 偷炉选到自己（同提交）
`card_user_list` 返回的好友列表**包含本人**，uin 不带前导 0（"4821992"），
而 `self.s.uin` 是 "0004821992"，旧版只按字符串比 → 发出 `opuin=自己`，
被拒「魔法学院规定不允许偷自己家的炉子！」，冷却 120s + 把自己拉黑 30 分钟。
`_pick_steal_friend` 统一按数值口径判「是不是我」。

### 4) 换卡箱被杂卡锁死（提交 `b135813`）
`_box_compaction` 只卖 10 面底卡 + 挪本套合成卡，**杂卡 owner=None 直接跳过** →
换卡箱 18 格里 11 张别的主题的 130~610 面历史卡永远腾不出来 → change_free 恒
0~2 → 买卡预算 0 → `_run_plan` 卡在第一个 buy op。
新增第 3 段：箱紧 + 保险箱有空位时，杂卡按面额降序挪进保险箱（只挪不卖），
腾到够一次「买 3 张立即投炉」即停。

### 运维结论
- 云端 8001 已 `POST /api/auto/stop`（running=false）；本地 8000 已启动 4821992
  的 tid=321（DP + 偷炉）。用户定调：**云端在国外机器、请求 QQ 慢，改本地跑**。
- 云端会话 token `0a53ddfa…`，本地 `y0w4s624…`；云端 sessions 在
  `/home/opc/mc/sessions`、日志 `/home/opc/mc/logs`（MC_LOG_DIR 被环境变量覆盖）。
- `/api/auto/status` 用 `X-MC-Token` 头在云端会返「未登录」，**改用 Cookie: mc_token=**
  才行（`_require_login` 走 SessionProxy，头那条路云端没生效）。
- 该号硬约束：保险箱 168/168 已满、换卡箱 18 格；这套要 15 格同时在箱 + 47 张
  底卡流量，腾位能力已耗尽，随时会撞箱 —— 需要用户自己清保险箱。
- 启动预检那行「189 张底卡 / 107.2h」是 `_calc_sets` 在 `_tick_collected` 为空时
  高估套数（4~6 套）的静态口径；运行期 `sets_now=1`、实际 39~45 张，不影响运行。

### DP 预买「保底一波」把换卡箱塞满（用户 13:08 报「卡箱满是因为你买了一堆底卡」）
- 真因（`dp_controller._run_plan`）：`abs_slots = _main_cap(ws) + soon_main`，
  3 主炉全在炼（剩 800~7900s）时 abs_slots=0，但 `base_quota = max(3, 0)` 硬保底
  → **每 tick 买 3 张底卡，本 tick 一张都投不出去**。15 分钟塞满 18 格换卡箱。
  修：`abs_slots == 0 and ws.change_free < 6` → base_quota = 0（`dfe8431`）。
  箱宽松时才保底（ablation「3★ 赚 2.2h」是 200 格箱口径，紧箱前提不成立）。
- 另一半：`_box_compaction` 只看「箱紧」就卖 10 面底卡，不问腾出的位有没有人接管
  → 卖完下 tick 又买回（真机逐行：13:00 卖犁头龟 / 13:08 买犁头龟 / 13:11 卖鹦鹉）。
  修：既无空主炉/快空出主炉、又无到点待收的炉 → 直接 return 0（`976644c`）。
- 实测改后 bought=0、腾位=0，引擎转入「等炉」正确态。
- ★**我之前判断错了（用户 13:21 当场纠正）**：库存口径是**两箱合计**（changebox
  + storebox），保险箱的卡照样能投炉（payload 带 slottype）、能上交。拿「换卡箱
  18 格」去比「need_slots=15」是错的 —— 按那个算法 13 张的 3★、16 张的 4★ 更没法
  炼，显然不成立。**永远别再拿单箱容量校验套卡张数。**
  正确数字（13:21 实测）：两箱套内 13 张（4833×2/4834×1/4835×2/4836×1/4837×2/
  4838×1/4839×1/4840×1/4842×2）+ 炉内 4839×2/4840×1/4841×2/4846×1，缺
  4843、4844、4845、4847 四种 —— 正是接下来要一路向上合的链，在正轨上。
- 保险箱 168/168 满的真实影响只有两条：① 多余合成卡挪不进去，省不出换卡箱格子；
  ② 出炉的卡只能落换卡箱。两箱空位 = 换卡箱 4 + 保险箱 0 = 4 格，取卡要 2 格够用，
  买一炉料 3 张也能周转 —— 是「紧」，不是「死」。
- 用户手投了 6 张到排队位（3 炉各 2 卡位），引擎默认不用排队位（`_main_cap` 只按
  并发，`MC_MAIN_QUEUE=1` 才放开；1★ 实测排队 8.12h vs 7.08h）——救火有效，非 bug。
### DP 买底卡规则（用户 13:28 再次定调：「卡没集齐时一个 10 面都不要买」）
- 现状核对：13:11 之后 bought=0、腾位=0（dfe8431+976644c 已生效），引擎在等炉。
- 但买料路径仍会「为还没到的炉提前备一波」：`jit_need` 从 cursor 起取头 n_wave(4)
  个 refine op 的底卡需求，不看该 op 的非底卡喂料是否已在箱 → 买了躺箱（真机
  13:00~13:08 那两批 6 张就是这么来的，13:11 又被卖掉）。
- 改法（`7f3b5a0`）：①`jit_need` 按波收集，非底卡喂料未齐的 op 直接跳过；
  ②`abs_slots==0` → base_quota 恒 0（去掉 change_free≥6 的囤卡口子）；
  ③上交前一次买齐仍走 `_album_prebuy`（非底卡全在箱 + 本套无在途）。
- **有意不做**「整波买不齐就整波不买」：真机换卡箱只剩 1~2 格，整波要 3 格会永久
  卡住（腾箱要先买、买要先腾箱）。
- 基准代价（`backend/_bench_wave.py`，18/200/1轮）：1★85 4.45→5.04、2★290
  14.43→15.01、3★59 45.41→45.01。1★/2★ 慢=拿掉物流补偿，换箱里不躺死卡。
### 用户推翻我的归因（14:00）：「1 tick 45s，一炉最多多 3 tick，怎么会多 0.6h」
- 他对。7f3b5a0 的「按波过滤买料」是错的归因。用 `backend/_probe_buywave_trace.py`
  逐 tick 记录 (cap/ref/buy/take/stock/pend) 实测：
  - OLD：356 tick，空炉空转 4 tick
  - NEW：403 tick，空炉空转 98 tick，其中 **t=13770~15500 连续 78 tick 零动作**
    （cap=1 有空主炉、stock=6、pend=2，什么都发不出）→ 47 tick 差全在这里。
- 机制：「非底卡喂料必须已在箱才买它的料」在链条初期恒不成立 → `jit_need` 恒空 →
  只走 `buy0_map` 兜底 → 一次只投 1 炉（原 4 炉）。时间线：NEW t=45/90/135/180/225
  逐炉铺满，OLD t=90 一次投满 4 炉；5 波 × 2~3 tick + 尾声后移 = 47 tick。
- 回退（`38c911d`）：只留 `abs_slots==0 → base_quota=0`（无 change_free 宽松口子）。
  基准零代价：1★85 4.45 / 2★290 14.43 / 3★59 44.99（原 45.41），重复 5 次完全一致
  （说明不是噪声，是真的会复现，靠时间线才定位）。
- ★教训：**基准差异远超「tick 量级」时，不要用机制直觉编解释，直接打逐 tick 时间线**。
  拿 「一炉多 3 tick × 12 炉 ≈ 36 tick」硬凑 47 tick 就是自我确认。
