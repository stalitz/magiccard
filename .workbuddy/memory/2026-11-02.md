## 修复：新开标签页不扫码却自动登录成另一个账号
- 现象：新标签显示二维码、一直不登录，过段时间自动进入主面板且是另一个已登录账号。
- 根因链：① 后端 `_resolve_session`(main.py:149-152) 无 token 时走 `_default_session()`，返回 `default` 账号（本地 8000 有 default.json，是旧单文件迁移来的）；云端 8001 无 default.json → /api/me 路由到 None → SessionProxy 抛 AttributeError → 500。② 前端 `pollOnce` 的 `expired` 兜底(app.js:438) 无脑接受任何 `logged_in:true` 的 /api/me 当本标签登录：冷启动（sessionStorage 空、未扫码）时后端把 default 账号顶回来 → `showDash` 自动登录。
- 修复：
  - 前端(app.js)：expired 兜底 `/api/me` 探活**仅在 `sawScanned`（本标签确实收到过 scanned=用户真扫码）时**才接受登录态；冷启动未扫码即使后端顶包也拒绝，只降速轮询。版本 bump 20261102a。
  - 后端(main.py `me()`)：开头加 `_current_session.get() is None → {"logged_in":False}`，避免无 default 时 500。
- 验证：本地 8000 + 云端 8001 的 `curl /api/me`（无 token）均返回 `{"logged_in":false}`；两边已重启、版本 20261102a。
- 铁律：`pollOnce` 的 expired 兜底绝不能把"无 token 请求返回的 default 账号登录态"当作"本标签已登录"——必须 `sawScanned` 闸。根因是后端 legacy「无 token=default 账号」与多账号隔离冲突；后端 default fallback 目前保留（legacy 用途），但新前端所有自动登录路径已加 token/sawScanned 守卫。

## 用户指正二：多余待收卡该「留炉不取」（fb3f28a）
- 用户原话：「现在只需要取出一个150, 再买6个10面的, 就能集齐一套, 卡箱刚好够... 但如果你取一个40卡出来, 卡箱可能就不够了, 你能看出这种情况, 把40卡放着不取, 等上交后再取吗」；并纠正我的措辞：「47是现在能用的卡箱, 200是理论上限, 不是已经开启的」（保险箱 `cur=47` 才是已开通格位，`max=200` 只是可开通上限）。
- 真机核对（tid=54）：套内 13 张 = 底卡 70~78（9 张 depth0）+ 40 面 79/80/81（depth1）+ 150 面 82（depth2）。箱内已有 70,77,78,79×2,80,81（6 款）；还缺 **71~76 六张底卡 + 82 一张 = 7 格**，两箱空位恰好 **7**（换卡箱 17-12=5、保险箱 47-45=2），**零余量**。炉里 82×2 + 80×1，只有一张 82 必需，另一张 82 与 80 是多余 → 取出来各占 1 格就会差一格凑不齐。
- 根因两处（互相打架）：
  1. tick 收卡（auto_refine.py:970+）是「炉里炼好就无条件取，箱满才 `_make_room` 腾位」，没有「这张卡对凑齐有没有贡献」的判断。
  2. `_album_prebuy` 的阻塞是「本套**任何**卡在炉里就不买底卡」→ 被故意留在炉里的多余卡会反过来**永久堵死**收尾买底卡。
- 修复：
  - 新增 `_collect_need`（队列各套凑齐还缺多少 distinct 张）+ `_should_defer_take`（三道闸：① 必需卡必取 ② 炉里多余待收卡 ≥4 张就强制取，卡位 7 个防积压 ③ 两箱空位 ≤ 凑齐缺口才延后）。
  - tick 收卡接入判断；取卡成功后同步 `stock_now[cid]` 与 `cap.change.used`，否则后续「够不够装下」的判据拿的是过期数据。
  - `_album_prebuy` 的 pending 收窄为 `any(pending>0 and stock.get(c)==0 for c in plan.ids)` —— 只让「还缺且必须出炉」的卡阻塞，多余卡留炉里不阻塞。
- 验证：离线按真机快照跑判据全绿（空位7/缺7 → 必需 82 照取；取走后空位6/缺6 → 第二张 82 与多余 80 均延后；积压 4 张强制取；箱位充裕不延后）。重启本地 + 云端均正常，引擎 running=true 无报错。
- ★ 铁律：**「取卡」和「凑齐」共用同一批箱位时，收卡必须先判断这张卡对凑齐有没有贡献**——多余卡留炉里（代价只是占一个炉位），等整套上交（格位一次性释放）后再取；反之，任何「炉里非空就不推进」的收尾阻塞条件都必须同步收窄，否则两条规则会互相锁死。

## 最高优先级规则落地：任何会卡住「集齐一套」的操作都延后（2026-11-02 14:50）
