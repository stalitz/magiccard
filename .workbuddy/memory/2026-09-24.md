## 变卡加回「星级」一级 + 下拉宽度按最长卡名自适应（用户 3 条反馈）

用户反馈：「换卡列表怎么把星级的选择去掉了，加回来；另外是在 web 页面，这个横向很长，完全可以把卡的
名字显示全，不要用 .. ；选择框的长度用最长的名字的宽度」。

### 根因（读旧版代码确认，不猜）
- 09-22 的变卡选择器是**三级下钻**（大弹窗 `#change-modal`：`#cb-star` → `#cb-theme-list` → `#cb-target-list`），
  星级是**第一级**。09-23 推翻弹窗改「一行内联三下拉」时，只保留了 套卡/目标卡/材料卡，**星级这一级丢了**
  → 用户说的「星级的选择去掉了」就是它（git: `fe5fe29` 有 `cb-star`，`58ce6d9` 起消失）。
- 卡名被截断的原因：`.cb-dd-list` 写死 `min-width:220px;max-width:340px`，且 `.pk .pk-n` 带
  `overflow:hidden;text-overflow:ellipsis` → 长名字出 `…`。

### 改法（`tools/rework_change_dd.py` 串行一次落盘，10 处替换全命中）
- **加回星级**：`#cb-change-bar` 最前面插 `.cb-dd`（`cb-dd-star-btn`/`cb-dd-star-list`）；
  `starSet = [...new Set(themes.map(t=>t.star))].filter(s=>s>0).sort(升序)`；`renderStarDD()` 列档位（`★★★` + `N 套`）；
  `renderThemeDD()` 改为 `if (!selStar) 提示「先选星级」` 否则 `themes.filter(t=>t.star===selStar)`。
  未选星级时套卡按钮 `disabled`，选星级后解禁（**初版漏了解禁 → 自查补上**）；换星级清空下游 + 禁用 目标/材料 按钮。
  提示语改为「星级 → 套卡 → 目标卡 → 材料卡」。
- **宽度**：`.cb-dd-list{width:max-content;min-width:150px;max-width:calc(100vw - 28px)}`（原 220/340 写死），
  `.pk .pk-n` 去掉 `overflow:hidden;text-overflow:ellipsis`（保留 `nowrap`）→ 宽度由**最长名字**决定、名字显示全。
- 版本号 `?v=20260923c` → `?v=20260924a`（服务在线已核对生效，纯前端无需重启）。

## 一键日常送礼：按等级从高到低送30人 + 逐人打日志（用户要求）

用户观察：游戏里还能送、等级高的才是活跃的；而原实现「送好友列表前30个（freegift 接口原始顺序）」
混着僵尸号。要求：按等级从高到低送30人，并把「送的哪个卡、送给哪个人」打进日志。

### 根因（读代码确认）
- 原 `gift_send(friends=None)` 走 `freegift_get_frds` 取全量好友、**只取前 limit(=30) 个**，`friends[:30]`，
  **全程无等级排序**，且 freegift 接口只解析 `uin`、无 exp。等级数据在另一条路 `card_user_list`
  （`/api/players`，main.py:1118 解析 `uin/nick/exp`）。
- 原 `_daily_send_gift` 只 log「送礼成功 N 人」，**没打具体送给谁**（底层 `gift_send` 其实返回了
  `batches:[{uins}]` 但上层丢弃了）。

### 改法
- `gift.py` 新增 `_player_index()`：拉 `card_user_list` 解析 `uin->(nick,exp)`（只读）。
- 新增 `_level_sorted_gift_friends(limit)`：freegift 池 × 等级表，按 exp 降序、排除自己(`session.uin`)、取前 limit；
  非玩家 exp=0 自然排末尾。
- `gift_send` 自动模式默认 `sort_by_level=True`，改用等级排序名单；返回 `sent_list=[{uin,nick,exp}]`。
- `daily._daily_send_gift` 透传 `sent_list`，文案「送礼 48面卡 成功 N 人（按等级从高到低）」。
- 前端 `dailyRun` 对 `sent_list` 逐人打日志：`· 48面卡 → uin（昵称）[exp N]`。
- 版本号 `?v=20260924a` → `?v=20260924b`。

- `py_compile`(gift.py/daily.py) + `node --check`(app.js) 均通过；服务在线已核对 20260924b。
- **后端改动需重启 uvicorn(:8000) 才生效**（纯前端改动不重启，但本次含 backend）。未自动重启（按规矩不动服务）。

## 每日送礼上限 30→50（游戏界面确认每天只能送 50 次）

用户复盘：「现在提示没有可送的好友，我在游戏里其实可以一直送，直到送完」→ 中断诊断后补一句
「看了游戏界面，每天只能送 50 次」。

### 根因
- 上一轮 `SEND_LIMIT=30` 写死上限，与游戏实际 50 次/天不符。
- 「没有可送的好友」真因：`freegift_get_frds` 只回「今天还没送的人」，今天用户在游戏里手动把 50 次
  额度用完后该接口返回空列表 → 不是名单逻辑丢人。诊断实测：该接口 `code:0` 但 `friends=[]`（total:0），
  而 `card_user_list` 有 194 个真实玩家（带 exp）。
- 原实现无每日额度跟踪，多次点击会重复尝试、且上限不对。

### 改法（`tools/rework_gift_daily.py` + `rework_gift_daily2.py` 串行落盘）
- `gift.py` 新增 `DAILY_CAP=50`；`_load_daily/_save_daily/gift_daily_remaining` 用
  `/tmp/mc_gift_daily.json` 跟踪本工具当天已送人数（按日期自动重置），跨多次点击/重启不超 50。
- `gift_friends` 兜底扫描：若 `data.friends` 空，扫描 data 里任何「元素带 uin 的 list」当好友池
  （接口字段名偶尔变动时防漏）。
- `_daily_send_gift`：先 `gift_daily_remaining()`，<=0 返回 `quota_done`（「今日额度已用完 50/50，明天再送」）；
  否则按当日剩余额度从 freegift 池取前 N（按 exp 降序），送完更新日计数；`sent>0` 文案带「今日 X/50」；
  列表空提示「游戏内可能已达 50 次上限，或好友都已送过」。
- 前端 `dailyRun` 对 `quota_done` 项用 `warn` 等级（非 err，是自然日上限）。
- 注意：游戏内手动送的不计入本地计数；但 freegift 额度用尽会返回空列表，工具如实报「无可送」，不会超发。
