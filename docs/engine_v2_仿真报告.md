## 结论

- 单套（单轮 + 多轮 + 无限炼）共 9 个场景：全部达成目标轮数、无溢出、无买卡失败。

- 多套（2套/3套/紧箱，含各 2~3 轮压力测试）共 6 个场景：全部精确达标（完成轮=目标轮）、无溢出、无买卡失败。

### 单套（1~5星，含多轮 / 无限炼）：✓ 通过

- 各星空箱起步独立炼成目标轮数；多轮连续交付无死锁、无溢出、无买卡失败；4★ 无限炼 375h 稳定产出 4 轮（炉占 90.8%），证实「collect→立即产下一套」管线正确。

- **峰值箱占用的正确口径（2026-10-22 应质疑重推）**：旧版峰值 166~201/218 是**仿真假象**——Step5 把 net_plan 的整套底卡需求（4★ 高达 176 张）一次性列入 emit_set，只限每 tick 买速（buy_cap≈13）、不限总量，箱里早早囤齐全部底卡等炼；实测峰值时刻 201 张中 176 张是底卡（94%）。同轮还发现并修复 **DP 分支底卡泄漏**：DP 投炉对底卡跳过 slot 分配 → `_do_refine` 收不到底卡 slot → 底卡永不进炉、全部泄漏囤积（实测 4★DP@800tick 炼 17 次却残留 164 张未耗底卡），已改为与贪心分支同口径。

- **JIT 理论峰值**（纯树模型：底卡即买即耗、只算合成卡等待队列）：1★ 5 / 2★ 11 / 3★ 20 / 4★ 26 / 5★ 12 张——与「套内 distinct 卡数」同量级（4★ 套仅 32 张 distinct，但完成一整套要买 176 张底卡、炼 72 次，因为同卡名被多个父卡复用）。修复后实测峰值：1★ 17 / 2★ 24 / 3★ 44 / 4★ 60 / 5★ 26（218 格）。**买卡量回归理论需求**：多套场景分毫不差（2套各3轮 bought=936=3×(176+136)、3套各1轮=389=176+136+77、紧箱各2轮=426=2×(77+136)）；单套 DP 4★ 179/176（每轮 +1 精炼的边界借还，+1.7%）、5★×2=156=78×2、3★/1★/2★ 均精确。全程零卖卡（修复前靠卖多余底卡循环）。

- **DP 调度已落地（3/4/5★ 单套，含多套尾部）**：单套高星改用 `sched_dp` 求类型级 RCPSP 最优精炼顺序（`dp_adapter.dp_order`），按 start time 升序做列表调度；轮次边界带真实持有量滚动重解（`dp_plan` 跨轮复用会漏掉中途库存，尾部激活场景实测 -8h）。多套共享段不走 DP（实测负，见文末评估）。实测对比贪心（`bench_dp.py`，修复后）：3★ 82.74→70.75h、4★ 95.39→81.39h、5★ 184.51→164.85h，高星收益最大（4★ 省 14h / 15%）。

- 真实炉位占用率（按建模 4 精炼槽，DP 后，单轮）：1★ 81% / 2★ 56% / 3★ 86% / 4★ 90% / 5★ 74%。**旧报告误用的「有炉在炼」比例 ~99% 已纠正——它不是槽填满率**。

- 5★ 峰值约 2.5/4 槽，受合成树依赖限制（加槽也救不了）；4★ 峰值触 4/4，但真实游戏尚有 2 个服务端队列槽引擎未用，属优化余地。

**多套关键修复（3套 [60,59,62] 此前「完成 1 轮后卡死 74553 tick」的根因）**：

1. **AdmissionControl 过度预留**：旧版按 `sum(runs)` 给 P0 静态预留箱位，但精炼**净腾 2 格**（耗 3 喂料 / 落 1 张）根本不长期占箱——等于预留了个不存在的压力，把其余套全 defer，而 P0 自己缺底卡又炼不动 → 全局停转。现改为「凡有净需求（runs>0）即准入」，箱位安全交给 Step5 买卡节流 + 精炼净负占用保证。

2. **买卡失衡**：旧版按 cid 顺序把一种底卡囤到 30+，其他类型凑不齐 3 合 1 的 trio → 炼不动、箱还囤爆。现改为**轮转平衡采购**（每轮每种底卡各买 1 张），让 trio 尽快成型、被精炼及时消耗。


**本轮修复（2026-10-22，回应用户「峰值不可能=把全部底卡买齐等炼」的质疑）**：

1. **JIT 拉动买卡**（替代表面积）：`due` = 即将能炼的合成卡（非底卡喂料全在箱/炉）的实例底卡喂料 + collect 在即的收藏底卡；depth-1 全底卡喂料首 tick 即拉动、上层随中间卡落箱逐层获得。实测 bought 从「超买+卖卡churn」变为**回归理论需求**（多套场景分毫不差），峰值箱 4★ 196→60、3★→44、5★→26、多套 214→68~84、紧箱 74→49/59。

2. **DP 分支底卡泄漏**：DP 投炉分支对底卡 `continue` 不分配 slot → 底卡永不进炉、泄漏囤积（4★DP@800tick 残留 164 张）。改为三种喂料一视同仁（底卡同样占箱位、同样被消耗），与贪心分支口径对齐。

3. **单套超标不停机**：旧版只查「全部达标」才停，已达标的套继续炼下一轮 → 占炉/囤箱、拖慢未达标套，还虚增 bought/refined（实测 2套·各3轮 4★ 被多炼 40 次=部分第4轮）。现按套达标即退出调度，完成轮数精确达标、bought 分毫不差。

4. **喂料半途失败回滚**：投炉时喂料取到一半失败（后一个喂料缺失），旧版已扣的 `stock_avail`/`taken` 不恢复 → 同 tick 后续投炉被误跳。现回滚后同 tick 口径准确。


**DP 求解器修复（上一轮）**：`sched_dp.solve` 的 `time_budget` 守卫原用 `time.time()`，在本测试环境的钟被 mock 成乱值导致预算失效、单次 DP 解算搜满 800 万节点烧 ~57s；改为 `time.perf_counter()` 后守卫稳定生效，单次解算锁定在 2.0s（~30 万节点、`bounded=True`），引擎端 `dp_plan` 又改为只解一次复用，彻底消除每轮重解开销（4★×3 轮从「墙钟 390s+ 且疑似卡死」降到 27s 干净跑完）。


**已知取舍**：贪心路径喂料半途失败回滚后，「浅层卡抢走深层卡喂料」的现象得到真实暴露（旧版的泄漏意外保护了关键路），4★ 贪心因此慢 ~3h（95.39 vs 旧预买口径 92.05）；DP 路径不受影响（单套高星生产路径）。JIT vs 预买整体占优（3★/5★ 更快、峰值减半、零浪费），后续可考虑「保护即将 priming 的深层卡的喂料」进一步优化贪心。


**多套 DP 接线评估（2026-10-22，回应「DP 价值是否真体现」的追问，全量数据见 `tests/_exp_rules.py`）**：

1. **套内排序键两度实测否决**：① cp 关键路序仅单套 3/4/5★ 有效（76.06/84.06/173.11 vs 贪心 82.74/95.39/184.51），多套共享箱时把单链卡前置→互抢枢纽喂料（同 tick slot 争用 ×9、完全空炉 tick ×3.5，2套·各3轮 412→430h）；② 按套 DP 序（dp_orders 接线）共享段同样负（2套 +8h、3套 +27h）——DP 模型按 3 炉独占求解，与共享 reality 不符。均回退，planner 留有注释。

2. **尾部 DP 是正解**：`len(active)==1`（先达标的套退出后最后一套独占资源）时自动激活 DP 分支，3套·各3轮 475.8→467.8h、2套 424.9→412.2h。

3. **联合多套 DP（2026-10-23 重做，推翻本条旧结论）**：旧拒绝理由两条均被证伪——① 「3 炉 DP 界 595.7h > 4 槽引擎 467.8h」是拿被砍偷炉的 DP 与完整引擎赛跑，不公平；② 「56+ 类型 2s 预算解不出优」是事实错误（公平实验 60s 预算下 253/315 节点、0.1/0.3s 即证完最优）。**公平 3 炉对比**（`tests/probe_fair_dp.py`，两边同禁偷炉）：联合 DP 静态解 2套 532.7h / 3套 595.7h（`opt`，非 bounded），比同炉数引擎（贪心+tailDP 540.9/602.9h）快 7~8h——DP 的全局序确实赢。

4. **联合 DP 接线实测为负（2026-10-23，同轮实验后半段）**：把联合序接进滚动引擎（轮边界重解）后全面变慢——2套·各3轮 411.5→433.6h（+22.1）、3套·各3轮 459.9→500.2h（+40.3）、2套单轮 141.4→148.8h；炉占 -5~8 点（97.1→92.2/89.3）、峰值箱 +35~56（73→108/84→140）。机制：DP 那 7~8h 是「静态全知」假设换来的（一次看全需求、底卡无限即时供应），滚动现实里 JIT 买卡有物流延迟、跨套争抢枢纽喂料、轮内序过时——静态 8h 优势被放大成 22~40h 劣势。已回退（基线数字复现 411.51h/97.1% 验证干净），联合序代码留 `dp_adapter.joint_dp_order`、探针留 `probe_fair_dp.py`，后续可试：更频重解 / DP 序仅作 tie-break / 把 JIT 物流延迟建进 DP 模型。

4. **滚动重规划（已落地）**：轮次边界（completed_rounds 变化）带真实持有量重解 DP（`dp_adapter` 的 stock/pending → net_plan 净减 + init_stock 免费素材）。单套多轮无差异（JIT 使轮界库存≈0，静态序本就够）；尾部激活场景受益：3套·各3轮 467.8→459.9h、2套 412.2→411.5h（炉占 95.4→97.1%）。修复了滚动引入的 KeyError（持有量覆盖需求的卡 runs=0 却仍被父卡 mats 引用 → 须以 need0=0 进实例）。

5. **DP 独占增量口径**：单套高星 DP 比最优简单规则（cp）再快 2.7~8.3h（3.2~7.0%）——真实但不大；此前「比贪心快 12~20h」里 70~80% 是关键路思想的价值。多套在**滚动执行形态**下吞吐已近理论界（炉占 97.1%），DP 静态序虽在公平 3 炉对比中再快 7~8h（见第 3 条），但该优势无法在滚动 JIT 现实中兑现（见第 4 条）；DP 的剩余价值在按套延迟（P0 反转，设计文档议题），不在 makespan。
